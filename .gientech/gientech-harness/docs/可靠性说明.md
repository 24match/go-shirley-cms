# 可靠性说明

## 当前可靠性目标面

本项目为医疗设备官网内容管理系统（CMS），基于 Go + Gin + SQLite 构建，主要可靠性保障场景包括：

- **后台管理操作**：图片上传、页面配置修改、内容管理等管理操作需要保证数据一致性
- **认证与会话**：JWT Token 认证需要保证会话安全与过期控制
- **文件存储**：图片上传与删除需要保证文件系统与数据库记录的同步
- **数据版本控制**：多语言文本支持版本管理，支持历史版本恢复

## 已有机制

### 错误处理与恢复

- **全局 Panic 恢复**：通过 [error_handler.go](../../../backend/middleware/error_handler.go) 中间件实现 defer + recover 机制，捕获未处理 panic 并记录日志，返回统一 500 错误响应
- **错误分类处理**：支持 Bind、Render、Private、Public 等错误类型的差异化响应
- **统一响应格式**：通过 [response.go](../../../backend/common/response.go) 定义标准 API 响应结构（code、message、data、timestamp）和完整错误码体系（400-503）

### 认证安全

- **JWT Token 认证**：Token 有效期 24 小时，过期自动失效，参见 [user_service.go](../../../backend/services/user_service.go)
- **密码加密存储**：使用 bcrypt 算法对用户密码进行加密，参见 [database.go](../../../backend/config/database.go)
- **请求日志记录**：认证失败、未授权访问等场景会记录日志，参见 [auth.go](../../../backend/middleware/auth.go)
- **CORS 中间件**：支持跨域请求控制，预检请求直接返回 204

### 数据可靠性

- **软删除机制**：Image 等模型使用 GORM 的 DeletedAt 字段实现软删除，支持数据恢复
- **自动迁移**：启动时自动执行表结构迁移，确保数据库 schema 与代码同步，参见 [database.go](../../../backend/config/database.go)
- **版本控制**：LanguageText 支持版本管理（LanguageTextVersion 表），可追溯修改历史并支持版本恢复
- **默认数据初始化**：首次启动自动创建默认管理员账户和页面配置

### 文件处理可靠性

- **防冲突命名**：图片上传使用时间戳 + 原文件名生成唯一文件名，避免冲突，参见 [image_service.go](../../../backend/services/image_service.go)
- **目录自动创建**：上传前自动执行 os.MkdirAll 确保 uploads 目录存在
- **文件与记录同步清理**：删除图片时同时删除文件系统中的文件和数据库记录，参见 [image_service.go](../../../backend/services/image_service.go)
- **文件保存错误处理**：SaveUploadedFile 失败时返回 500 错误，避免数据不一致

### 请求验证

- **参数绑定验证**：使用 Gin 的 binding 标签进行必填字段校验，如登录接口的 username/password
- **存在性检查**：更新、删除操作前先查询记录是否存在，避免无效操作

## 关键风险点

- **无显式超时控制**：当前代码中未发现 HTTP 客户端调用或数据库操作的显式超时配置
- **无重试机制**：数据库操作、文件操作失败后无自动重试逻辑
- **单点数据库**：使用 SQLite 嵌入式数据库，不支持高可用部署
- **无请求限流**：未发现针对 API 的限流或防刷机制
- **日志级别单一**：当前仅使用 log.Printf，未区分 INFO/WARN/ERROR 等级别
- **敏感配置硬编码**：JWT Secret 在代码中硬编码，建议移至环境变量
- **无健康检查接口**：未发现用于负载均衡或容器编排的健康检查端点
- **批量操作原子性**：批量上传时单条失败可能导致部分成功，无事务回滚
