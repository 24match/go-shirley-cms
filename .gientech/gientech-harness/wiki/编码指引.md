## 概述

本文档定义了医疗设备官网 CMS 系统项目的编码规范和最佳实践，旨在确保代码质量、可维护性和团队协作效率。所有开发人员必须严格遵循本规范，通过代码审查和自动化工具确保规范的执行。

项目基于 Go + Gin + SQLite 构建，采用前后端分离架构，后端使用 Go 1.25.0 开发，前端使用原生 HTML/CSS/JS。

### 核心原则
- **可读性优先**: 代码应该易于理解和维护
- **一致性**: 保持代码风格和结构的一致性
- **简洁性**: 避免过度复杂的设计和实现
- **安全性**: 遵循安全编码最佳实践
- **性能**: 在保证可读性的前提下优化性能

## 代码风格规范

### 基本格式规范

#### 缩进和空格
- 使用 **Tab** 进行缩进（Go 语言标准）
- 行尾不允许有空格
- 文件末尾保留一个空行
- 每行代码长度不超过 120 个字符

#### 大括号规范
```go
// 推荐：大括号不换行（Go 语言标准）
package main

import (
    "fmt"
)

func main() {
    if err := config.InitDB(); err != nil {
        panic(err)
    }
    r := config.SetupRouter()
    r.Run(":8080")
}

// 不推荐：大括号换行
package main

import (
    "fmt"
)

func main()
{
    if err := config.InitDB(); err != nil
    {
        panic(err)
    }
}
```

#### 空行规范
- 类成员之间使用一个空行分隔
- 方法之间使用一个空行分隔
- 逻辑块之间使用空行提高可读性
- 导入语句分组，组间使用空行分隔

### 导入语句规范

```go
// 1. 标准库
```

## 命名规范

### 类命名规范

#### 结构体名
- 使用 PascalCase（首字母大写的驼峰命名）
- 结构体名应该是名词，具有描述性
- 避免缩写，除非是广泛认知的缩写

```go
// 推荐
type UserService struct { }
type ImageController struct { }
type PageConfig struct { }

// 不推荐
type usrSvc struct { }
type imgCtrl struct { }
type pgCfg struct { }
```

#### 接口命名
- 接口名通常以 "er" 结尾或使用描述性名词
- 接口实现类可以添加 "Impl" 后缀（如需要）

```go
// 推荐
type UserRepository interface { }
type PaymentService interface { }
```

### 方法命名规范

#### 方法名
- 使用 camelCase（首字母小写的驼峰命名）
- 方法名应该是动词或动词短语
- 布尔方法使用 Is、Has、Can 等前缀（首字母大写）

```go
// 推荐
func (c *UserController) Login(ctx *gin.Context) { }
func (s *UserService) CreateUser(user *models.User) error { }
func IsValidEmail(email string) bool { }
func HasPermission(permission string) bool { }

// 不推荐
func (c *UserController) UserLogin(ctx *gin.Context) { }
func (s *UserService) Create(user *models.User) error { }
func CheckEmail(email string) bool { }
```

### 变量命名规范

#### 变量名
- 使用 camelCase
- 变量名应该具有描述性
- 避免使用单字母变量名（除了循环变量）

```go
// 推荐
userName := "john"
pendingOrders := make([]*Order, 0)
maxRetryCount := 3

// 不推荐
u := "john"
list := make([]*Order, 0)
n := 3
```

#### 常量命名
- 使用全大写字母和下划线分隔
- 常量名应该具有描述性

```go
// 推荐
const DefaultUserRole = "USER"
const MaxLoginAttempts = 3
const APIVersion = "v1"
```

### 文件命名规范

- 文件名使用小写字母和下划线分隔（Go 语言惯例）
- 测试文件以 `_test.go` 结尾
- 文件名应该反映其内容

```
// 推荐
user_controller.go
user_service.go
response.go
database.go

// 不推荐
UserController.go
userController.go
```

## 代码结构规范

### 类结构规范

#### 结构体成员顺序
```go
type ExampleStruct struct {
    // 1. ID 字段
    ID uint `gorm:"primaryKey" json:"id"`

    // 2. 时间戳字段
    CreatedAt time.Time      `json:"createdAt"`
    UpdatedAt time.Time      `json:"updatedAt"`
    DeletedAt gorm.DeletedAt `gorm:"index" json:"deletedAt,omitempty"`

    // 3. 业务字段（按重要性排序）
    Username string `gorm:"uniqueIndex;not null" json:"username"`
    Password string `gorm:"not null" json:"password"`
    Role     string `gorm:"default:'admin'" json:"role"`
}
```

### 方法结构规范

#### 方法长度
- 单个方法不超过 50 行
- 如果方法过长，考虑拆分为多个小方法
- 每个方法只做一件事

#### 参数规范
- 方法参数不超过 5 个
- 如果参数过多，考虑使用参数对象
- 使用结构体处理复杂参数

```go
// 推荐：使用参数结构体
type LoginRequest struct {
    Username string `json:"username" binding:"required"`
    Password string `json:"password" binding:"required"`
}

func (c *UserController) Login(ctx *gin.Context) {
    var req LoginRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        common.JSONBadRequest(ctx, "Invalid request parameters")
        return
    }
    // 业务逻辑
}

// 不推荐：参数过多
func Login(ctx *gin.Context, username, password, role, token string, expire int) {
    // 实现逻辑
}
```

```go
// User represents a user in the system with authentication credentials.
type User struct {
```

```go
// Login authenticates a user and returns a JWT token.
// Parameters:
//   - username: the user's username
//   - password: the user's password
// Returns:
//   - user: the authenticated user
//   - token: JWT token string
//   - error: any error that occurred during authentication
func (s *UserService) Login(username, password string) (*models.User, string, error) {
    // 方法实现
}
```

### 行内注释规范

#### 注释原则
- 解释"为什么"而不是"做什么"
- 避免显而易见的注释
- 注释应该与代码同步更新

```go
// 推荐：解释业务逻辑
// 检查用户是否在试用期内，试用期用户有特殊限制
if user.IsInTrialPeriod() && user.GetUsageCount() > TRIAL_LIMIT {
    return errors.New("trial limit exceeded")
}

// 推荐：解释复杂算法
// 使用 bcrypt 进行密码哈希，确保密码安全存储
hashedPassword, err := bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)

// 不推荐：显而易见的注释
// 设置用户名为"admin"
user.Username = "admin"
```

## 异常处理规范

### 错误处理原则

#### 错误返回
- 函数应该返回 error 作为最后一个返回值
- 调用者必须检查并处理错误
- 不要忽略错误返回值

```go
// 推荐：正确处理错误
func InitDB() error {
    var err error
    DB, err = gorm.Open(sqlite.Open("medical.db"), &gorm.Config{})
    if err != nil {
        return err
    }
    return nil
}

// 不推荐：忽略错误
func InitDB() {
    DB, _ = gorm.Open(sqlite.Open("medical.db"), &gorm.Config{})
}
```

#### 错误包装
- 使用 fmt.Errorf 包装错误，添加上下文
- 使用 errors.Is 和 errors.As 进行错误判断

```go
// 推荐：错误包装
if err := DB.Where("username = ?", username).First(&user).Error; err != nil {
    return nil, "", fmt.Errorf("failed to find user: %w", err)
}

// 推荐：错误判断
if errors.Is(err, gorm.ErrRecordNotFound) {
    return nil, "", errors.New("user not found")
}
```

### 资源管理

```go
// 推荐：使用 defer 确保资源释放
func ReadFile(path string) ([]byte, error) {
    file, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer file.Close()
    
    return io.ReadAll(file)
}
```

## 日志规范

### 日志级别使用

#### 日志级别定义
- **Error**: 系统错误，需要立即处理
- **Warn**: 警告信息，可能影响系统功能
- **Info**: 重要的业务流程信息
- **Debug**: 调试信息，仅在开发环境使用

```go
// 推荐：合理使用日志级别
func (c *UserController) Login(ctx *gin.Context) {
    var req LoginRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        log.Printf("Invalid request parameters: %v", err)
        common.JSONBadRequest(ctx, "Invalid request parameters")
        return
    }

    user, token, err := c.userService.Login(req.Username, req.Password)
    if err != nil {
        log.Printf("Login failed for user %s: %v", req.Username, err)
        common.JSONUnauthorized(ctx, "Invalid credentials")
        return
    }

    log.Printf("Login successful for user %s", req.Username)
    common.JSONSuccess(ctx, gin.H{"token": token, "user": user})
}
```

### 日志格式规范

#### 日志消息格式
- 包含必要的上下文信息
- 避免敏感信息泄露

```go
// 推荐：结构化日志
log.Printf("User login successful - userId: %d, username: %s", user.ID, user.Username)

// 不推荐：记录敏感信息
log.Printf("User login - username: %s, password: %s", username, password) // 安全风险
```

## 测试代码规范

### 测试命名规范

#### 测试类命名
- 测试文件名以 `_test.go` 结尾
- 测试文件应该与被测试文件在同一个包下


#### 测试函数命名
- 使用描述性的测试函数名
- 遵循 `Test[功能]_[场景]` 格式


### 测试结构规范

#### 测试函数结构
```go
func TestUserService_Login_ValidCredentials(t *testing.T) {
    // Arrange - 准备测试数据
    userService := NewUserService()
    expectedUser := &models.User{Username: "admin", Role: "admin"}
    
    // Act - 执行被测试的方法
    user, token, err := userService.Login("admin", "admin123")
    
    // Assert - 验证结果
    if err != nil {
        t.Errorf("Expected no error, got %v", err)
    }
    if user == nil {
        t.Error("Expected user, got nil")
    }
    if token == "" {
        t.Error("Expected token, got empty string")
    }
}
```

## 性能优化规范

### 数据库操作规范

#### 查询优化
```go
// 推荐：使用 First 而不是 Where 获取单条记录
var user models.User
if err := DB.Where("username = ?", username).First(&user).Error; err != nil {
    return err
}

// 推荐：使用 Select 只查询需要的字段
var users []User
DB.Model(&User{}).Select("id", "username", "role").Find(&users)

// 不推荐：查询所有字段
var users []User
DB.Find(&users) // 可能返回大量数据
```

#### 批量操作
```go
// 推荐：使用批量插入
users := []models.User{
    {Username: "user1", Password: "pass1"},
    {Username: "user2", Password: "pass2"},
}
DB.Create(&users)

// 不推荐：循环插入
for _, user := range users {
    DB.Create(&user) // 多次数据库调用
}
```

### 集合使用规范

#### 切片初始化
```go
// 推荐：指定初始容量
users := make([]*models.User, 0, expectedSize)

// 不推荐：未指定容量，可能频繁扩容
users := []*models.User{}
```

### 敏感信息处理

#### 密码处理
```go
// 推荐：使用 bcrypt 加密密码
hashedPassword, err := bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)
if err != nil {
    return err
}

// 验证密码
if err := bcrypt.CompareHashAndPassword([]byte(user.Password), []byte(password)); err != nil {
    return errors.New("invalid credentials")
}

// 不推荐：明文存储密码
user.Password = password // 安全风险
```

#### JWT Token 处理
```go
// 推荐：使用安全的密钥和过期时间
expirationTime := time.Now().Add(24 * time.Hour)
claims := &models.Claims{
    UserID: user.ID,
    Role:   user.Role,
    RegisteredClaims: jwt.RegisteredClaims{
        ExpiresAt: jwt.NewNumericDate(expirationTime),
    },
}
token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
tokenString, err := token.SignedString(config.JWTSecret)
```

#### 配置安全
```go
// 注意：JWTSecret 应该从环境变量读取，而不是硬编码
// 当前实现（需改进）：
var JWTSecret = []byte("medical-device-cms-secret-key-2024")

// 推荐：从环境变量读取
var JWTSecret = []byte(os.Getenv("JWT_SECRET"))
```

### CORS 配置

```go
// 当前实现：允许所有来源（开发环境）
func CORSMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Writer.Header().Set("Access-Control-Allow-Origin", "*")
        c.Writer.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
        c.Writer.Header().Set("Access-Control-Allow-Headers", "Content-Type, Authorization")
        if c.Request.Method == "OPTIONS" {
            c.AbortWithStatus(204)
            return
        }
        c.Next()
    }
}

            return
        }
        c.Writer.Header().Set("Access-Control-Allow-Origin", origin)
```

## 代码审查规范

### 审查检查清单

#### 功能性检查
- [ ] 代码是否实现了预期功能
- [ ] 边界条件是否得到正确处理
- [ ] 异常情况是否得到适当处理
- [ ] 性能是否满足要求

#### 代码质量检查
- [ ] 代码是否遵循命名规范
- [ ] 代码结构是否清晰合理
- [ ] 注释是否充分且准确
- [ ] 是否存在代码重复

#### 安全性检查
- [ ] 输入验证是否充分
- [ ] 敏感信息是否得到保护
- [ ] 是否存在安全漏洞
- [ ] 权限控制是否正确

### 审查流程

#### 审查步骤
1. **自检**: 开发者完成代码自检
2. **工具检查**: 运行 `go fmt`、`go vet` 等工具
3. **同行审查**: 至少一名同事进行代码审查
4. **修改完善**: 根据审查意见修改代码
5. **最终确认**: 审查者确认修改结果
