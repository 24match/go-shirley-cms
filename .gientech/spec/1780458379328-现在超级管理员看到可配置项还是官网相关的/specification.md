# 需求文档：超级管理员租户配置项优化

## 1. 引言

### 1.1 功能概述

本需求旨在优化超级管理员的配置管理功能，将超级管理员的可配置项从官网相关内容（如 ModuleConfig、PageConfig、ContentItem 等）转变为**租户级别的配置项**。超级管理员应关注租户的整体管理和配置，而不是租户内部官网内容的细节。

### 1.2 背景与目标

**当前问题**：
- 超级管理员目前只能管理租户的基本信息（名称、域名、状态等）
- 缺乏对租户功能模块、资源配额、订阅计划等高级配置的管理能力
- 超级管理员与租户管理员的职责边界不清晰

**目标**：
- 明确超级管理员与租户管理员的职责分离
- 超级管理员专注于租户级别的宏观配置
- 租户管理员专注于官网内容的微观配置

### 1.3 关键利益相关者与用户

| 角色 | 职责 | 使用场景 |
|------|------|----------|
| 超级管理员 | 管理所有租户、配置租户级别的功能和配额 | 创建新租户、调整租户订阅计划、启用/禁用租户功能模块 |
| 租户管理员 | 管理租户内部的官网内容配置 | 配置 Banner、关于我们、产品展示等官网内容 |

### 1.4 预期价值与收益

1. **职责清晰**：超级管理员与租户管理员职责分离，避免权限混乱
2. **管理高效**：超级管理员可批量管理租户配置，提升运营效率
3. **安全可控**：租户级别的配置隔离，避免越权操作
4. **商业灵活**：支持不同订阅计划的功能差异化配置

## 2. 需求

### 2.1 用户管理

#### 需求 1.1：超级管理员租户列表查看

**用户故事**：作为一名超级管理员，我希望查看系统中所有租户的列表和状态，以便了解整体运营情况。

**验收标准（EARS 格式）**：
1. 当超级管理员访问租户管理页面时，系统应展示所有租户的列表，包含租户名称、状态、订阅计划、创建时间等关键信息
2. 如果租户数量超过分页阈值，系统应支持分页展示，每页默认显示 10 条记录
3. 系统应支持按租户状态（active/disabled/pending/suspended）筛选租户列表
4. 系统应支持按订阅计划（free/pro/enterprise）筛选租户列表

#### 需求 1.2：超级管理员租户详情查看

**用户故事**：作为一名超级管理员，我希望查看单个租户的详细信息，包括其配置项和使用情况，以便进行精细化管理。

**验收标准（EARS 格式）**：
1. 当超级管理员点击租户列表中的某个租户时，系统应展示该租户的详细信息
2. 系统应展示租户的基本信息（名称、域名、状态、订阅计划）
3. 系统应展示租户的配置项（功能模块开关、资源配额使用情况）
4. 系统应展示租户的统计信息（用户数量、图片数量、内容项数量等）

### 2.2 核心功能

#### 需求 2.1：租户功能模块配置

**用户故事**：作为一名超级管理员，我希望为每个租户配置可用的功能模块，以便根据订阅计划控制租户的功能访问权限。

**验收标准（EARS 格式）**：
1. 当超级管理员编辑租户配置时，系统应提供功能模块开关列表供选择
2. 系统应支持的功能模块包括：图片管理、页面配置、多语言管理、联系表单、内容管理
3. 如果租户的某个功能模块被禁用，系统应在租户管理员尝试访问该功能时返回权限不足提示
4. 系统应记录功能模块配置的变更历史

#### 需求 2.2：租户资源配额配置

**用户故事**：作为一名超级管理员，我希望为每个租户设置资源使用配额，以便控制资源消耗和实现订阅计划差异化。

**验收标准（EARS 格式）**：
1. 当超级管理员创建或编辑租户时，系统应提供资源配额配置选项
2. 系统应支持的配额类型包括：最大图片数量、最大存储空间（MB）、最大内容项数量、最大用户数量
3. 如果租户的资源使用达到配额上限，系统应阻止新资源的创建并提示配额已满
4. 系统应支持超级管理员手动调整租户配额

#### 需求 2.3：租户订阅计划管理

**用户故事**：作为一名超级管理员，我希望管理租户的订阅计划和过期时间，以便实现商业化运营。

**验收标准（EARS 格式）**：
1. 当超级管理员创建或编辑租户时，系统应提供订阅计划选择（free/pro/enterprise）
2. 系统应支持设置订阅过期时间
3. 如果租户订阅已过期，系统应在租户登录时提示续费，并可根据配置限制功能访问
4. 系统应支持订阅计划升级/降级操作

### 2.3 数据管理

#### 需求 3.1：租户配置数据存储

**用户故事**：作为一名系统架构师，我希望设计合理的租户配置数据存储结构，以便高效支持配置查询和更新。

**验收标准（EARS 格式）**：
1. 系统应在数据库中创建租户配置表（TenantConfig），与 Tenant 表一对关联
2. TenantConfig 表应包含：租户 ID、功能模块配置（JSON）、资源配额（JSON）、订阅配置（JSON）
3. 系统应在创建租户时自动创建对应的配置记录
4. 系统应支持配置数据的版本记录（可选）

#### 需求 3.2：租户配置变更审计

**用户故事**：作为一名审计人员，我希望记录所有租户配置的变更操作，以便追踪配置变更历史。

**验收标准（EARS 格式）**：
1. 当超级管理员修改租户配置时，系统应自动记录审计日志
2. 审计日志应包含：操作人、操作时间、租户 ID、变更前的配置、变更后的配置
3. 系统应支持超级管理员查看租户配置变更历史
4. 审计日志应至少保留 180 天

### 2.4 API / 集成

#### 需求 4.1：租户配置 API

**用户故事**：作为一名前端开发者，我希望有完整的租户配置 API 接口，以便实现管理界面的功能。

**验收标准（EARS 格式）**：
1. 系统应提供 GET `/api/superadmin/tenants/:id/config` 接口用于获取租户配置
2. 系统应提供 PUT `/api/superadmin/tenants/:id/config` 接口用于更新租户配置
3. 系统应提供 POST `/api/superadmin/tenants/:id/quota/reset` 接口用于重置租户配额使用统计
4. 所有租户配置 API 应仅限超级管理员访问，返回 403 错误给非超级管理员

#### 需求 4.2：租户功能检查 API

**用户故事**：作为一名前端开发者，我希望有 API 可以检查租户是否启用了某个功能模块，以便动态展示界面。

**验收标准（EARS 格式）**：
1. 系统应提供 GET `/api/tenant/features` 接口用于获取当前租户的功能模块状态
2. 系统应提供 GET `/api/tenant/quota` 接口用于获取当前租户的资源配额使用情况
3. 这些接口应集成到现有的租户认证流程中，租户管理员登录后自动获取

### 2.5 安全

#### 需求 5.1：租户配置访问控制

**用户故事**：作为一名安全管理员，我希望确保租户配置只能被超级管理员访问，以防止越权操作。

**验收标准（EARS 格式）**：
1. 当非超级管理员尝试访问租户配置 API 时，系统应返回 403 Forbidden 错误
2. 当租户管理员尝试访问其他租户的配置时，系统应返回 403 Forbidden 错误
3. 系统应使用 JWT Token 中的角色信息进行权限校验
4. 系统应记录所有权限拒绝的尝试日志

#### 需求 5.2：配置变更验证

**用户故事**：作为一名安全管理员，我希望在配置变更时进行数据验证，以防止非法配置数据。

**验收标准（EARS 格式）**：
1. 当超级管理员提交租户配置时，系统应验证配置数据的格式和合法性
2. 系统应验证资源配额值为正整数且不超过系统上限
3. 系统应验证功能模块名称为预定义的有效值
4. 系统应返回具体的验证错误信息给前端

### 2.6 性能

#### 需求 6.1：配置查询性能

**用户故事**：作为一名系统用户，我希望租户配置查询响应迅速，以获得良好的使用体验。

**验收标准（EARS 格式）**：
1. 当超级管理员获取租户配置时，系统应在 200ms 内返回响应
2. 系统应使用数据库索引优化租户配置的查询性能
3. 系统应支持配置数据的缓存（可选），缓存过期时间不少于 5 分钟

### 2.7 错误处理

#### 需求 7.1：配置操作错误处理

**用户故事**：作为一名系统用户，我希望在配置操作失败时获得清晰的错误提示，以便了解问题原因。

**验收标准（EARS 格式）**：
1. 当租户配置操作失败时，系统应返回明确的错误代码和错误信息
2. 系统应区分不同类型的错误（验证错误、数据库错误、权限错误）
3. 系统应记录详细的错误日志用于故障排查
4. 系统应在前端展示友好的错误提示信息

### 2.8 用户体验

#### 需求 8.1：超级管理员配置界面

**用户故事**：作为一名超级管理员，我希望有直观的租户配置管理界面，以便高效完成配置操作。

**验收标准（EARS 格式）**：
1. 系统应在租户管理页面提供"配置"按钮，点击后进入租户配置编辑界面
2. 配置界面应按类别组织配置项（功能模块、资源配额、订阅计划）
3. 系统应提供配置的保存和取消操作
4. 系统应在配置保存成功后展示成功提示信息

#### 需求 8.2：租户管理员视图

**用户故事**：作为一名租户管理员，我希望看到当前租户的配置状态和配额使用情况，以便了解可用资源和功能。

**验收标准（EARS 格式）**：
1. 系统应在租户管理员 Dashboard 展示功能模块状态（已启用/已禁用）
2. 系统应在租户管理员 Dashboard 展示资源配额使用情况（已使用/总额度）
3. 系统应在资源接近配额上限时展示警告提示（如达到 80%）
4. 系统应隐藏或禁用不可用的功能模块入口

## 3. 术语定义

| 术语 | 定义 |
|------|------|
| 超级管理员 | 系统最高权限用户，角色为 `superadmin`，可管理所有租户 |
| 租户管理员 | 租户级别的最高权限用户，角色为 `tenant_admin`，管理租户内部配置 |
| 功能模块 | 系统提供的可配置功能单元，如图片管理、页面配置等 |
| 资源配额 | 租户可使用的资源上限，如图片数量、存储空间等 |
| 订阅计划 | 租户的付费等级，决定功能模块和资源配额的默认值 |

## 4. 假设与依赖

### 4.1 假设

1. 系统已有完整的租户（Tenant）数据模型和基础 CRUD 接口
2. 系统已有 JWT 认证机制和角色权限控制
3. 系统已有审计日志（AuditLog）模型用于记录操作日志

### 4.2 依赖

1. 依赖现有的 `Tenant` 模型和 `TenantService` 服务
2. 依赖现有的 JWT 认证中间件和权限校验机制
3. 依赖现有的 `AuditLog` 审计日志服务
4. 前端依赖 React + TypeScript 技术栈
